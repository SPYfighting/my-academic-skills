# Quality gates for editable scientific figures

Visual fidelity and native editability are separate requirements. Both must pass. Fewer objects do not compensate for an unrecognizable biological structure or apparatus.

## Before drawing

Create a brief object checklist for the figure. The user's stated priorities decide which objects require source-level detail and which may be schematic. For each key object, record:

1. Its scientific meaning and the visible features that identify it without a caption.
2. Its silhouette, perspective, color hierarchy, and spatial relation to neighboring objects in the reference or description.
3. The intended native parts and continuous paths that a researcher may edit later.

Use the actual reference crop when supplied. For description-only requests, use domain-correct visual conventions and inspect a paper or authoritative reference if an object's appearance is uncertain. Do not invent measured values or claim a generic icon represents a specific machine.

## Hard acceptance checks

- **Recognition at normal size:** hide or ignore the label and inspect the object at the intended slide viewing size. The target reader should distinguish its type from a generic box or decorative squiggle. If it fails, add the missing identifying parts.
- **Reference features:** compare each critical object side by side with its source crop. Every recorded identifying feature must be present and placed coherently. Shapes can be simplified, but a feature that carries identity cannot be omitted.
- **Scientific semantics:** preserve arrow direction, process order, material flow, major biological topology, and exact labels. A diagram that looks plausible but changes meaning fails.
- **Visual craft:** check stroke consistency, alignment, whitespace, perspective, layering, legibility, and color balance on the full slide. Enlarge critical crops to catch missing joints or malformed curves, then return to normal size to verify recognition.
- **Native editing:** confirm zero embedded picture objects for requested editable artwork, live text, independently selectable functional parts, and one PowerPoint freeform for each continuous line where practical. Repeated wells or ticks with common styling may share a compound path.

Inspect the rendered PPTX and the actual PowerPoint view when the application is available. Record pass/fail and the evidence for each critical object, separately from deliberately simplified objects. If a hard check fails, revise the drawing before delivery. If application access is blocked, report that specific verification gap rather than claiming the final file was visually checked there.

For example, in a workflow like the Baker reference, a double helix needs two alternating rails and base-pair rungs; a liquid-handling setup needs a pipetting head, plate, workdeck and collection compartment; a chromatography stack needs distinct modules, solvent bottles and column; an analysis monitor needs the appropriate plot; and a robotic enclosure needs a gantry or head, deck and output plate. These are example identity cues, not a fixed icon library.
